# Инструкция по использованию сервера

## 1. Установка и первый запуск

Установите Go 1.24 или новее и Python 3.11, добавьте их в PATH. Проверка:

```powershell
go version
python --version
```

В PowerShell из корня проекта:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup.ps1
powershell -ExecutionPolicy Bypass -File .\scripts\start.ps1
```

`setup.ps1` создаёт `.venv`, устанавливает версии из `face-service/requirements.lock.txt`, скачивает две модели с проверкой контрольных сумм, загружает Go-зависимости и собирает `bin/server.exe`. Повторный запуск допускается. Он не меняет глобальные пакеты Python.

`start.ps1` запускает приватный Python-сервис на `127.0.0.1:8001`, ждёт готовности и запускает Go. Python работает в скрытом процессе, его диагностика записывается в `.runtime/face.err.log`. При завершении Go скрипт останавливает только созданный им процесс Python. При занятом порту 8001 скрипт прекращает запуск, чтобы не использовать случайный чужой сервис.

Перейдите на [http://localhost:8080](http://localhost:8080), введите пароль из консоли. Пароль, указанный через `ADMIN_PASSWORD`, в консоль не выводится.

## 2. Веб-панель

### Добавление сотрудника

1. Откройте «Сотрудники» → «Добавить сотрудника».
2. Укажите ФИО: от 2 до 120 символов после удаления пробелов по краям.
3. Введите UID карты: 7 байт, то есть 14 шестнадцатеричных символов. Интерфейс переводит ввод в верхний регистр.
4. Выберите JPEG или PNG до 2 МБ и 4 мегапикселей. На снимке должно быть одно хорошо видимое лицо, желательно анфас.
5. Нажмите «Сохранить сотрудника» и дождитесь обработки.

Если на фото нет лица или найдено несколько лиц, профиль не создаётся. UID должен быть уникальным. Фото не помещается ни в SQLite, ни в каталог загрузок; вместо него сохраняется числовой вектор.

### Блокировка и удаление

«Блокировать» запрещает проход по карте, сохраняя профиль. «Разблокировать» восстанавливает доступ. Удаление требует подтверждения в панели: профиль и вектор удаляются, исторические события с ФИО остаются в журнале. Отдельной очистки журнала в интерфейсе нет.

### Журнал

Время и фильтр даты используют **Москву, UTC+3**. Поиск по ФИО поддерживает кириллицу без учёта регистра; поиск UID также допускает нижний регистр. Фильтры комбинируются. Страница содержит до 50 событий; кнопки «Назад» и «Далее» переключают страницы. Фильтры можно сбросить одной кнопкой.

При открытой вкладке данные обновляются каждые 5 секунд. Индикатор готовности распознавания проверяется примерно каждые 30 секунд. При возвращении к скрытой вкладке или нажатии «Обновить» данные и состояние проверяются сразу. Если соединение потеряно, интерфейс показывает, что данные устарели.

Счётчики «Успешные проходы» и «Отказы» относятся к текущему московскому дню; они не меняют период при фильтрации таблицы. График показывает число всех попыток по часам этого дня. Счётчик сотрудников включает активные и заблокированные профили.

### Проверка без платы

Откройте «Проверка доступа», укажите UID и **JPEG**, нажмите «Проверить доступ». Запрос идёт через рабочую ручку `/api/v1/access`; событие сохраняется в журнале. Для отрицательной проверки используйте неизвестную карту, фотографию другого человека или фото без лица.

При включённом ключе устройства форма работает по сессии администратора; ключ не раскрывается браузеру. ESP32 требуется собственный заголовок `X-Device-Key`.

## 3. Переменные окружения

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `APP_ADDR` | `127.0.0.1:8080` | Адрес прослушивания Go-сервера |
| `DB_PATH` | `data/access.db` | Файл SQLite, относительно рабочей папки или абсолютный путь |
| `ADMIN_PASSWORD` | Случайный пароль при запуске | Не менее 10 символов; один администратор |
| `FACE_SERVICE_URL` | `http://127.0.0.1:8001` | HTTP(S)-адрес сервиса распознавания |
| `FACE_THRESHOLD` | `0.363` | Порог косинусного сходства, число в диапазоне `(0; 1]` |
| `DEVICE_API_KEY` | Пусто | Если задан, плата обязана передать `X-Device-Key` |
| `COOKIE_SECURE` | `false` | `true` добавляет Secure к cookie; использовать с HTTPS |
| `MODEL_DIR` | `face-service/models` | Каталог моделей Python-сервиса |

Для локального запуска задавайте переменные в том же PowerShell:

```powershell
$env:ADMIN_PASSWORD = 'your-long-admin-password'
$env:DB_PATH = 'data/access.db'
$env:FACE_THRESHOLD = '0.363'
.\scripts\start.ps1
```

**Локальные скрипты не читают `.env` автоматически.** Файл `.env` предназначен для Docker Compose. Все значения хранятся в окружении запускающего процесса; изменение требует перезапуска сервисов.

`start.ps1 -Lan` временно задаёт `APP_ADDR=0.0.0.0:8080`. После выхода скрипт восстанавливает прежнее значение. Если `FACE_SERVICE_URL` указывает на другой сервис, скрипт не запускает локальный Python.

## 4. Подключение ESP32-CAM

1. Запустите `start.ps1 -Lan` или Go с `APP_ADDR=0.0.0.0:8080`.
2. Узнайте IPv4 компьютера через `ipconfig` и разрешите входящий TCP-порт 8080 в частной сети при необходимости.
3. В прошивке задайте URL `http://IP_КОМПЬЮТЕРА:8080/api/v1/access`.
4. Соберите multipart-запрос с текстовым полем `uid` и файловым полем `photo`. JPEG нужно отправить бинарно, без base64.
5. Если сервер настроен с ключом, передайте `X-Device-Key`.
6. Открывайте замок только при успешно разобранном JSON с логическим `access: true`. Таймаут, обрыв сети, неверный JSON и любое другое значение должны оставлять замок закрытым.

Таймаут устройства рекомендуется выставить не короче 25 секунд: Go ждёт Python не более 15 секунд и дополнительно записывает журнал. При обычном локальном распознавании ответ значительно быстрее; это нужно измерить на целевом компьютере.

По ТЗ поддерживаются **только 7-байтные UID**. RC522 может встретить карты с другими длинами UID: они будут отклонены. Для их поддержки сначала согласуйте новый контракт, затем измените проверку сервера, схему и прошивку.

Пример теста стандартным Python, без сторонних библиотек:

```powershell
python scripts/access_client.py `
  --server http://192.168.1.20:8080 `
  --uid 04A1B2C3D4E5F6 `
  --photo C:\photos\capture.jpg
```

При включённом ключе добавьте `--key YOUR_DEVICE_KEY`. Код выхода клиента: `0` — разрешено, `2` — отказ, `1` — ошибка соединения.

## 5. Ручной запуск и Linux

Windows, первое окно PowerShell:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app:app --app-dir face-service --host 127.0.0.1 --port 8001 --no-access-log
```

Второе окно:

```powershell
$env:ADMIN_PASSWORD = 'your-long-admin-password'
.\bin\server.exe
```

Linux/macOS:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r face-service/requirements.lock.txt
.venv/bin/python face-service/download_models.py
go mod download
mkdir -p bin
go build -trimpath -o bin/server ./cmd/server
.venv/bin/python -m uvicorn app:app --app-dir face-service --host 127.0.0.1 --port 8001 --no-access-log
# Во втором терминале из корня проекта:
ADMIN_PASSWORD='your-long-admin-password' ./bin/server
```

В сборку Go включены HTML/CSS/JS, поэтому отдельный фронтенд-сервер и Node.js для эксплуатации не нужны. Изменение веб-файлов требует пересборки Go.

## 6. Docker Compose

```powershell
Copy-Item .env.example .env
# Замените пароль в .env.
docker compose up --build -d
docker compose ps
docker compose logs -f server face
```

Первые сборки скачивают Go/Python-зависимости и около 39 МБ моделей. Go стартует после успешной проверки готовности Python. Порт Python наружу не публикуется. Порт 8080 опубликован для панели и платы.

Остановка: `docker compose down`. После изменения кода: `docker compose up --build -d`. После изменения `.env`: `docker compose up -d`. Имя Compose-проекта задано явно: `kontur`, чтобы запуск работал и из папки с кириллицей. Данные находятся в именованном томе `kontur_access-data` при стандартном имени проекта.

## 7. Хранение и резервное копирование

Локальная база находится в `data/access.db`. SQLite использует WAL; во время работы могут присутствовать `access.db-wal` и `access.db-shm`. Не копируйте один `.db` активного сервера как полную резервную копию.

Простой способ: остановите систему и затем скопируйте `data` в защищённую папку:

```powershell
# После Ctrl+C и остановки сервера:
$backupDir = 'backups\access-' + (Get-Date -Format 'yyyyMMdd-HHmmss')
New-Item -ItemType Directory -Path $backupDir -Force | Out-Null
Copy-Item -LiteralPath 'data\access.db' -Destination $backupDir
```

Для копирования без остановки используйте SQLite Backup API. Например, установленный Python 3.11:

```powershell
python -c "import sqlite3; source=sqlite3.connect('data/access.db'); target=sqlite3.connect('backup.db'); source.backup(target); target.close(); source.close()"
```

Восстановление: остановите сервер, сохраните текущую базу отдельно, восстановите согласованный файл из резервной копии в новый каталог и задайте `DB_PATH` на этот файл. Не накладывайте восстановленный `.db` на старые `-wal`/`-shm`. Векторы лиц являются биометрическими данными: ограничьте доступ к базе и резервным копиям.

Сессии администратора хранятся в памяти и не попадают в резервную копию. После рестарта нужно войти заново.

## 8. Диагностика

| Симптом | Что проверить |
|---|---|
| «Распознавание недоступно» | `.runtime/face.err.log`, `FACE_SERVICE_URL`, наличие моделей, `http://127.0.0.1:8001/health` |
| Порт 8001 занят | Остановите предыдущий экземпляр или укажите внешний `FACE_SERVICE_URL` |
| `unknown_uid` | Карта зарегистрирована? UID совпадает побайтно? Ровно 14 символов? |
| `inactive_user` | Разблокируйте сотрудника в панели |
| `no_face_detected` | Освещение, положение головы, чёткость; лицо должно занимать заметную часть кадра |
| `multiple_faces` | В кадре должен быть один человек |
| `face_mismatch` у владельца | Проверьте эталон, освещение и камеру; проведите калибровку, не снижайте порог без измерений |
| `invalid_request` | Multipart boundary, имена полей, целостность JPEG, размер до 2 МБ, не более 4 Мп |
| `unauthorized_device` | `X-Device-Key` должен совпасть с `DEVICE_API_KEY` |
| `server_error` | Права/свободное место для SQLite и журналы Go |
| ESP32 не видит сервер | `-Lan`, IPv4, брандмауэр, общая сеть, отсутствие изоляции Wi-Fi-клиентов |
| Постоянно возвращается экран входа | Пароль/перезапуск; не включён ли `COOKIE_SECURE=true` при обычном HTTP |
| `429` на входе | Восемь попыток за минуту исчерпаны; дождитесь конца окна |
| Не скачиваются зависимости | Интернет, корпоративный прокси, доступ к PyPI, GitHub и Go proxy |

Публичная ручка `/health` проверяет доступность базы Go; готовность распознавания проверяется отдельно в `/api/admin/health` после входа. Реальный сервис не подменяет распознавание разрешающей заглушкой при сбое.
