# Разработка и сопровождение

## 1. Окружение

Рабочая конфигурация: Go 1.24+, Python 3.11, SQLite через `modernc.org/sqlite`, FastAPI/OpenCV/Pillow. Go-зависимости закреплены в `go.mod`/`go.sum`. Прямые Python-зависимости перечислены в `requirements.txt`, полное окружение — в `requirements.lock.txt`.

Node.js и Playwright нужны только для браузерных проверок. HTML/CSS/JS не требуют bundler или npm при обычном запуске.

## 2. Проверки

Из корня проекта, после `scripts/setup.ps1`:

```powershell
$env:GOCACHE = Join-Path (Get-Location) '.gocache'
go test ./...
go vet ./...
.\.venv\Scripts\python.exe -m unittest discover -s face-service -p 'test_*.py' -v
node --check internal/app/web/app.js
```

Тесты Go не требуют сети, физических карт, камеры или моделей. Используется SQLite в памяти и тестовый HTTP-сервис. Никакие реальные данные не изменяются.

Сквозная проверка:

```powershell
go build -trimpath -o bin/server.exe ./cmd/server
.\.venv\Scripts\python.exe scripts/smoke_test.py
```

Скрипт создаёт временную базу под `.runtime`, выбирает свободные локальные порты, запускает Go и настоящий Python, выполняет проверку и останавливает оба процесса. В Windows завершается всё дерево дочернего Python-процесса, поскольку исполняемый файл venv может запускать дополнительный процесс.

При первом запуске скачиваются два тестовых изображения из официального репозитория OpenCV в `.runtime/fixtures`. Это тестовые данные, не данные сотрудников. После первой загрузки тест работает без сети. Запуск в среде с запретом на создание/завершение дочерних процессов может требовать отдельного разрешения этой среды.

Сквозные сценарии: регистрация, повторный UID, разрешение после повторного JPEG-сжатия, неизвестная карта, чужое лицо, отсутствие лица, групповое фото, блокировка/разблокировка, остановка Python, удаление и сохранность истории.

## 3. Браузерная проверка

Нужны Node.js, установленный Edge и Playwright:

```powershell
# Загрузка браузера не нужна: используется установленный Edge.
$env:PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD = '1'
npm ci --ignore-scripts
npm run test:browser
```

Сначала выполните `smoke_test.py`, чтобы получить тестовую фотографию в `.runtime/fixtures`. Браузерный тест самостоятельно запускает сервисы с временной базой и проверяет вход, регистрацию, UID, проход, поиск, мобильную вёрстку, блокировку/разблокировку, удаление, выход и JS/CSP-ошибки. Скриншоты сохраняются под `.runtime`, база удаляется после остановки процессов.

Другой установленный канал Playwright можно выбрать через `PLAYWRIGHT_CHANNEL`, например `chrome`. Если браузер не установлен, установите соответствующий браузер или адаптируйте запуск Playwright. Это инструмент разработчика, а не зависимость рабочего сервера.

## 4. Сборка после изменений

```powershell
gofmt -w cmd internal
go test ./...
go vet ./...
go build -trimpath -o bin/server.exe ./cmd/server
```

Изменение HTML/CSS/JS также требует этой сборки: web-файлы встроены в бинарник. Python-код используется напрямую, поэтому после изменения нужно перезапустить Python-сервис. Для Docker выполните `docker compose up --build -d`.

## 5. Как добавлять ручку

1. Добавьте регистрацию маршрута в `App.Handler` с явным методом.
2. Административный маршрут оберните в `a.admin(...)`.
3. Ограничьте тело запроса, проверьте типы и обязательные поля.
4. SQL разместите в `store.go`, значения передавайте параметрами.
5. Добавьте описание в `API.md` и проверку изменённого поведения.
6. Не возвращайте вектор лица или секрет устройства в публичных JSON.

## 6. Как менять схему базы

`CREATE TABLE IF NOT EXISTS` создаёт новую базу, но не меняет уже существующие таблицы. Для изменения схемы добавьте версионную миграцию, например через `PRAGMA user_version`, и тест обновления предыдущей схемы. Перед миграцией сделайте согласованную резервную копию SQLite.

Не добавляйте каскадное удаление журнала при удалении пользователя: история и неизвестные карты должны сохраняться независимо.

## 7. Как менять модели и порог

`FACE_THRESHOLD` влияет только на сравнение косинусного сходства. Выше порог — строже совпадение, ниже — легче пройти. Выбор порога делайте на двух наборах: реальные владельцы своих карт и чужие люди с теми же картами, при разных освещении, положении головы и качестве JPEG.

При смене модели обновите `model_manifest.py`, загрузчик, сведения `/health` и документацию. Новую модель нельзя просто применить к старым векторным профилям: зарегистрируйте лица заново или введите версию модели в схему и поддержите миграцию. Фото пользователей не сохраняются, поэтому автоматически пересчитать эталоны из текущей базы невозможно.

Файлы моделей закреплены размером и SHA-256. Проверки выполняются при загрузке и старте Python. Замена файла под тем же именем с другой контрольной суммой приведёт к отказу запуска.

## 8. Что проверять перед распространением

Запустите модульные и сквозные проверки, пересоберите бинарник и проверьте регистрацию/проход на настоящих кадрах ESP32. Убедитесь, что инструкция соответствует фактической конфигурации и что вместе с исходниками не распространяются `.env`, пароли, cookie, данные SQLite или резервные копии.

Контейнерная конфигурация и Windows-скрипты — разные способы эксплуатации. Выполнение тестов локального сервера не доказывает, что Docker-образы собраны и проверены на конкретном хосте: это отдельно отмечается в [VERIFICATION.md](VERIFICATION.md).
